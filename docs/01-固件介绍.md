## 固件包的来源

索尼没有为 ILCE-7RM3A 发布过固件包，所以本机没有官方恢复路径。

这一条是核实过的：官方支持页的下载列表里只有配套软件，没有固件条目。

```
https://www.sony.com/electronics/support/e-mount-body-ilce-7-series/ilce-7rm3a/downloads

Creators' Cloud Web        10/28/2026
Imaging Edge Desktop        05/14/2026
Transfer & Tagging          10/14/2025
Imaging Edge Webcam         07/11/2024
Imaging Edge Mobile         10/31/2023
PlayMemories Home           02/14/2019
```

对照：ILCE-7RM3（不带 A）的官方页有固件下载，最新 3.10。

研究时用的是同平台的 ILCE-7RM3（A7R3）3.10 官方包做只读参考。两者关系：

| | ILCE-7RM3 3.10 | ILCE-7RM3A 1.00 |
|---|---|---|
| 是否有官方包 | 有 | 无 |
| `libObj.so` 大小 | 19,483,804 字节（包内） | 19,484,036 字节（机上） |
| 大小差 | — | +232 字节 |

字节层面的差异：

```
同偏移相同字节          8.08%
完全相同的 256B 块      0.25%
完全相同的 4KB 块       0.11%
钩点处 32 字节          0 个字节相同
```

用 `tools/sigscan.py` 扫两个文件的对照（同一个签名库）：

下表左边一列是**签名库里记录的地址**，也就是**相机这份构建（A7R3A 1.00）**的地址。
中间是固件包（A7R3 3.10）里实际扫到的位置，右边是差值。

```
签名                相机 A7R3A 1.00    包 A7R3 3.10      差值（包-相机）
cp_recv_loop_hook      0xA31226        0xA31136            -240
plt_ObjMsg_ctor        0x0FF7B8        0x0FF654            -356
plt_AddParam           0x1027E4        0x102684            -352
Get_id                 0x34D840        0x34D7C0            -128
createEvent_hook       0x3C039E        未命中                —
plt_ParamStd_ctor      0x102B34        未命中                —
plt_IssueCommandAsync  0x0FD2A0        未命中                —
```

**相机那份全部命中且差值为 0**（签名库就是从它取的）。
**包那份有的偏移几百字节、有的根本对不上。**

⚠ 不要把 0xA31136 当成相机上的钩点。它只存在于固件包里，在相机上钩这个地址
会落在别的函数中间，4 字节补丁横穿指令边界，必崩。

**⇒ 地址绝不可借用。** 这也是本项目要用特征码定位的原因，见[特征码定位](附录/特征码定位.md)。

复现这条对照：

```bash
python tools/sigscan.py locate --file <固件包里的 libObj.so>
python tools/sigscan.py locate --file <从相机 dump 的 libObj.so>
```

音效资源是例外：固件包里的 30 个 `.bin` 与本机未改动的 30 个文件逐字节相同，
所以可以当作音效的恢复源。

## 存储

`partinf.conf` 定义了 `nflasha1`…`nflasha30`，其中多数是零长度保留项。相机 `/proc/partitions` 里实际存在 16 个编号分区（编号到 `nflasha23`，中间有空洞），另有整盘 `nflasha` 和 `nflashaB0/B1`。挂载的是这些：

| 设备 | 挂载点 | 大小 | 文件系统 | 权限 | 内容 |
|---|---|---|---|---|---|
| `nflasha7` | `/` | 8 MB | ext2 | ro | 根文件系统 |
| `nflasha15` | `/usr` | 300 MB | ext2 | ro | 库、二进制、音效资源（固件包内 792 文件 / 182 MB） |
| `nflasha2` | `/setting` | 20 MB | vfat | rw | 相机设置、Backup |
| `nflasha3` | `/system` | 48 MB | vfat | rw | 系统数据 |
| `nflasha10` | `/tmp`、`/etc` | 12 MB | vfat | rw | 临时文件、配置 |
| `nflasha11` | `/log` | 500 MB | vfat | rw | 日志 |
| `nflasha12` | `/cert` | 40 MB | vfat | rw | 证书 |
| `nflasha18` | `/lens` | 20 MB | vfat | rw | 镜头数据 |

分区原始表（起址 + 大小，来自 `partinf.conf`）：

```

```

零长度的保留项（`nflasha8`、`9`、`14`、`19`–`22`、`24`–`30`）不建设备节点，未列入。

**`/` 和 `/usr` 是 ext2 且只读挂载。** 要改里面的文件必须先
`mount -o remount,rw /usr`。这是本项目所有持久化改动的前提。

`/usr` 分区 300 MB，固件包里的内容 792 个文件 / 182 MB。相机上实际剩多少空间，
要在你自己的机器上看：

```sh
busybox df -h /usr
```

即使固件版本相同，不同机器的剩余空间也可能不同（文件系统保留块、碎片、使用历史）。
本项目不给出固定剩余空间；改文件前先看这个数，`/usr` 不够时不要另存整个 `.so` 的副本。

## 关键模块

`/usr/lib/` 下这些是本项目用到的：

| 模块 | 大小 | 作用 |
|---|---|---|
| `libObj.so` | 19,484,036 B | 主体业务逻辑。CP 收包循环、声音系统、Backup、菜单节点都在这 |
| `CautionConfig.so` | 10,114,464 B | 设置菜单的结构与属性表 |
| `viewUnified2.so` | 10,752,440 B（固件包里同名文件 10,752,148 B，不可混用） | UI 渲染、菜单显示 |
| `libosal_uipc.so` | 26,692 B | IPC 底层，`.bss` 尾部有可写空闲区 |
| `ModelCautionConfig.so` | 6,764 B | 名字和 CautionConfig 相近，定位基址时别搞混 |
| `viewUnified4.so` | 2,753,064 B | 其他 UI 页 |
| `viewUnified6.so` | 525,332 B | 其他 UI 页 |

运行期基址（`/proc/155/maps` 实测）：

```
libObj.so            0x05DCA000
libosal_uipc.so      0x04050000
viewUnified2.so      0x15008000
CautionConfig.so     0x15AC0000
ModelCautionConfig.so 0x0C4EA000
```

**模块内偏移 + 基址 = 运行期地址。** 例：`libObj.so` 的 fileVA `0xA31226` →
运行期 `0x05DCA000 + 0xA31226 = 0x067FB226`。

## 系统架构

相机是双系统：

```
Linux 侧（im.elf）
  管界面、文件、设置、USB
  没有音频设备 —— /dev 下没有声卡
  
RTOS 侧
  管影像、快门、发声
  真正的喇叭接在这边

两侧通过 /dev/uipc 通信
```

**这一条决定了整个项目的方向。** Linux 侧能改的东西很多（文件、进程内存、菜单资源、
Backup 属性），但它没有喇叭。所以在 Linux 里"调用播放 API"永远只是**请求**，
真正发声的是另一颗核。

注入方式（改 `.so`、`LD_PRELOAD`、`/proc/<pid>/mem`）从来不是瓶颈，它们最后都汇到
同一条 IPC 上。要找的是"发什么消息、什么时候发"。

## 进程

主进程 `im.elf`，服务模式下 pid 155，177 个线程，常规优先级和实时优先级混合。
loadavg 常年在 80 上下——这是相机自身的基线，不是本项目造成的。

**⇒ 在 CP 收包线程里做任何阻塞操作都会拖垮整条流水线。** 这是载荷设计的第一条约束，
见[编写载荷](教程/04-编写载荷.md)。

## 音效资源

`/usr/share/avsystemsound/`：

- 30 个 `.bin`，合计 156,096 字节
- `beeplist.txt` 4,619 字节，56 条记录，其中 26 条指向 `None`

音效格式和槽位选择见[替换音效](教程/07-替换音效.md)。

## USB 模式

相机有两个 USB 模式：

```
普通模式  054C:0D99   海量存储器 / MTP
服务模式  054C:0336   诊断用，可以执行 shell 命令
```

服务模式需要 libusb 驱动（Windows 下用 Zadig 装 libusb-win32）。切换命令由
Sony-PMCA-RE 提供，见[依赖与环境](02-依赖与环境.md)。

服务模式是索尼自己保留的诊断接口，本项目没有破解它的认证，也没有绕过固件签名。
