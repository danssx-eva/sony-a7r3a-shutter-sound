# 教程 07 · 替换音效

相机上的提示音来自 30 个 `.bin` 文件。换掉其中一个，拍照时就会播放替换后的音效。不涉及代码注入，也不需要改 Sony 的任何二进制，是整个项目里风险最低的改动。

本项目一直用 `0x07` CAUTION 这个槽位，对应 8640 字节。下文以它为例；
换别的槽位按文件名和字节数对应替换。

**注意：只替换音效不会让电子快门发声。** 电子快门下相机本来就不播任何提示音，
让它在快门时响是[教程 05](05-打钩子.md) 和 [06](06-持久化到闪存.md) 的注入方案做的事。
本篇只改变**相机原生提示音**的音色——装好钩子之后，快门时播放的才是你换的这段音频。

## 替换的含义

这一步是**覆盖**：`cp` 上去之后，原厂文件的内容从相机上消失，不是多出一个声道。

ILCE-7RM3A 没有官方固件包（官方下载页只有配套软件，没有固件条目），所以下载不回来。
唯一的恢复途径是替换之前自己备份的那一份。

**替换前必须做两件事：**

1. 把原厂文件拉回电脑（下一步的命令）
2. 记下它的 MD5

否则一旦替换，这个文件就永久变了。

## 前置条件

- 一台 ILCE-7RM3A，固件 1.00。其他机型、其他固件，字节数和槽位语义都不保证
- 一根 USB 数据线，电脑上能进相机的服务模式。仓库内置了 Sony-PMCA-RE，在 `vendor/` 下
- Python 3.10 以上，不需要第三方库（转换器是纯标准库）
- 一个 WAV 或 MP3 音效文件
- 相机上原厂 `Dslr_Emnt_High_Caution.bin` 的一份副本。唯一的回滚素材

## 第一步：确认相机是原厂状态

```bash
python tools/verify_environment.py --check-all
```

这个工具只读。它核对的项包括相机连接、`libObj.so` 指纹、钩子字节、音频信号属性表、音效格式、Backup 属性。全部一致后再继续。

有不匹配就停止，先按[特征码定位](../附录/特征码定位.md)在本地固件上重新确认地址。

同时把相机上的原厂文件拉回电脑：

```bash
python tools/camera/a7r3a_pull.py --out logs/watch \
    --path /usr/share/avsystemsound/Dslr_Emnt_High_Caution.bin
```

输出在 `logs/watch/<时间戳>/usr_share_avsystemsound_Dslr_Emnt_High_Caution.bin`，8640 字节。记录该文件的 MD5。

## 第二步：把音频转成相机格式

相机音效不是裸 PCM，是每 32 字节一块的预测编码，细节见[声音系统](../附录/结构规格.md)。转换器在 `examples/` 下：

```bash
# 先看目标槽位的字节数
python examples/convert_audio.py --list-targets

# 任意音频先转成 24 kHz 单声道 16 位 WAV
ffmpeg -i my.mp3 -ar 24000 -ac 1 -sample_fmt s16 my.wav

# 编码成相机格式
python examples/convert_audio.py --input my.wav --target caution --out my.bin
```

没有素材、想先跑通流程，用内置合成音：

```bash
python examples/convert_audio.py --preset click --target caution --out my.bin
```

`--target caution` 会自动把输出大小定成 8640 字节。也可以手工指定 `--size`，但必须是 64 的倍数（编码器按 64 字节补齐）。

`my.bin` 正好 8640 字节。文件长度与槽位绑定。

## 第三步：把生成的文件解回来听

```bash
python examples/convert_audio.py --decode my.bin --wav-out check.wav
```

输出的回环误差（同一编解码器往返，只反映实现自洽，不证明设备接受的格式）是"编码后解回来"与"原始样本"的最大差值。正常范围是几十到几百（16 位有符号满幅 ±32767）。上千说明素材太响、有突变，或者参数不对，不要部署。

加上 `--json` 可以得到机器可读的摘要。

如果只想跳过响度处理、原样编码，加 `--no-loudness`。默认处理链是：峰值归一化 → 高频提升（`y[i] = x[i] + 0.8 * (x[i] - x[i-1])`，听感更脆）→ 动态压缩 → tanh 软限幅 → 缩放到峰值 32000。

## 第四步：传到相机

用 `push_files.py` 传到 `/log/w/`（超过 28 KB 会自动分段）：

```bash
python tools/camera/push_files.py --file my.bin
```

然后在相机上覆盖、刷盘：

```sh
busybox mount -o remount,rw /usr
busybox cp /log/w/my.bin /usr/share/avsystemsound/Dslr_Emnt_High_Caution.bin
busybox sync
busybox fsync /dev/nflasha15
busybox sync
busybox mount -o remount,ro /usr
busybox md5sum /usr/share/avsystemsound/Dslr_Emnt_High_Caution.bin
```

这里的 `fsync /dev/nflasha15` 是关键。`sync()` 不会让 eMMC 把自己的写缓存刷下去，只有 fsync 到块设备才会。少了这一条，你会得到"当场读回一模一样、重启全部回滚"的假象。

相机上整个文件的 MD5 等于本地 `my.bin` 的 MD5。

只比前 32 字节会漏掉"前面是静音、后面才是声音"的情况，这个坑踩过。覆盖就行，不要另存副本；
先看 `busybox df -h /usr`，剩余空间每台机器可能不同。

## 第五步：拔电池冷启动

音效在启动时加载。普通 `reboot` 不一定重载 RTOS 侧（这块闪存是 WBI 热启动快照），所以必须拔电池，等十几秒再装回开机。

开机后 `/proc/uptime` 归零，证明真的重启了。改前记一次，改后比一次。

## 第六步：验证

拍一张，听声音。没变就见下表。

| 现象 | 先查这个 |
|---|---|
| 完全没变 | 文件大小对吗？整文件 MD5 对上了吗？拔电池了吗 |
| 声音变了但很小 | Backup 音量没拉到 7，见下一节 |
| 变成了噪音 | 编码参数不对，回第三步看回环误差 |
| 文件换成静音了 | 正常，说明格式对了，只是素材本身没内容 |
| 相机起不来 | 立刻拔电池，用原厂文件按第四步的仪式写回 |

## 把音量拉大

见[调整音量](08-调整音量.md)。只调你替换掉的那个槽位，别碰其他的。

## 回滚

把第一步拉回来的原厂文件改名并传回相机：

```bash
cp logs/watch/<时间戳>/usr_share_avsystemsound_Dslr_Emnt_High_Caution.bin orig_caution.bin
python tools/camera/push_files.py --file orig_caution.bin
```

然后按同样的仪式写回去：

```sh
busybox mount -o remount,rw /usr
busybox cp /log/w/orig_caution.bin /usr/share/avsystemsound/Dslr_Emnt_High_Caution.bin
busybox sync
busybox fsync /dev/nflasha15
busybox sync
busybox mount -o remount,ro /usr
busybox md5sum /usr/share/avsystemsound/Dslr_Emnt_High_Caution.bin
```

MD5 回到第一步记下的值，再拔电池冷启动。

## 怎么选槽位

`/usr/share/avsystemsound/` 下有 30 个 `.bin`。`beeplist.txt` 共 56 条记录，其余 26 条指向
`None`（通道存在但没挂文件）。

30 个槽位分三类：

| 类别 | 数量 | 说明 |
|---|---|---|
| 不能播 | 6 | priority 6，换什么都无声 |
| 建议保留 | 3 | 对焦锁定、自拍、自拍2秒 —— 这是日常会听到的三个 |
| 可以替换 | 21 | 其余全部 |

**能播的判据是 priority：5 及以下能播，6 播不出来。**

### 建议保留的 3 个

| soundId | 名称 | 什么时候会响 |
|---|---|---|
| `0x04` | FORCUSLOCK | 对焦锁定，"嘀"一声 |
| `0x0D` | SELFTIMER | 自拍倒计时 |
| `0x2C` | SELFTIMER_2SEC | 自拍 2 秒倒计时 |

动这三个会改变你平时拍照能听到的提示音。

### 21 个可替换槽位，按相机自己会不会响排

| soundId | 名称 | 相机什么时候会自己播 | 安全度 |
|---|---|---|---|
| `0x30` | WIFI_TOGGLE | 开 WiFi | 最安全 |
| `0x31` | WIFI_TOGGLE_OFF | 关 WiFi | 最安全 |
| `0x32` | WPS_CONNECT | WPS 连接 | 最安全 |
| `0x33` | WPS_PBC | 按 WPS 键 | 最安全，29760 字节，最长的槽位 |
| `0x34` | WPS_PUSH | WPS 推送 | 最安全 |
| `0x1C` | SWITCH_MODE | 切换模式 | 安全 |
| `0x26` `0x27` | BACK_CANCEL | 按返回 / 取消 | 菜单操作时响 |
| `0x08` `0x09` `0x0A` | SELECT / MOVE | 菜单选择、上下移 | 菜单操作时响 |
| `0x0E` `0x0F` `0x10` `0x11` | MENU / OPTION | 开关菜单、选项 | 菜单操作时响 |
| `0x2A` `0x2B` | WHEEL_UP / DOWN | 拨轮 | 拨轮时响 |
| `0x18` | TAP | 触摸屏 | 触摸时响 |
| `0x28` `0x29` | ON / OFF | 开关某项设置 | 部分场景响 |
| `0x07` | CAUTION | 警告提示 | 本项目当前用这个 |

**推荐用 WiFi / WPS 那五个（`0x30`–`0x34`）**：不操作 WiFi 配网就永远不会触发，和拍照体验
完全不冲突。其中 `0x33` 有 29760 字节，能放下 1201 ms 的音效。

本项目用 `0x07` CAUTION，代价是电池警告之类的场景会响成快门声。想彻底避开这一点就换到
`0x33`。

### 为什么不能新增一个槽位

第一个想法是不动任何原厂文件，往 `beeplist.txt` 里那 26 个 `None` 空槽挂文件，新增第 31 个
音效。实测走不通：改 `/tmp/beeplist.txt` 和改 `/usr/share/avsystemsound/beeplist.txt`
都不影响播放，连把 CAUTION 改成指向另一个现成音效也没有变化。

结论是 beeplist 不是播放时用的映射表。详细记录见[死路清单 G-01](../附录/死路清单.md)。

## 这一条路的边界

- 必须等长替换。相机按该 soundId 对应文件的原始长度读取，长度必须与槽位一致。
- 必须冷启动才生效。
- 换的是"相机原生提示音"，不是"电子快门专属声音"。电子快门下相机本来不播提示音，那是注入方案解决的事，见[注入载荷](05-打钩子.md)。
- 这一路改的是闪存里的音效资源，`/usr` 没有签名校验，但写坏一样起不来。

## 出问题看哪里

- 写进去不生效、重启回滚：死路清单 A 组，全是持久化的坑
- 音效格式、回环误差、编码器参数：死路清单 D-01、D-02
- 验证方法（只比前 32 字节、一次传大文件）：死路清单 D-12、D-13
- 为什么必须这样写、为什么不能边走边试：找[逆向方法](../附录/逆向方法.md)
