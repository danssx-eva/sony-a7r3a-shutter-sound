# 教程 04 · 编写载荷

文件：`docs/patches/payload.bin`
运行期地址：`0x05F5E8D8`（libObj 基址 `0x05DCA000` + fileVA `0x1948D8`）

## 结构

```
偏移        内容
0x000-0x0DF 代码（224 字节，78 条指令）
0x0E0-0x0E7 重放原 4 字节 + 跳回（8 字节）
0x0E8-0x0EF 填充（8 个 0x00 字节，不会被执行）
```

## 代码分五段

### 段一：保存现场，取消息

```asm
push.w {r0, r1, r2, r3, r4, r5, r6, r7, r8, ip, lr}
sub.w  sp, sp, #0x30
ldr.w  r8, [r7, #0x14]        ; r8 = 消息指针（被钩函数里 r7 指向栈帧，+0x14 是 msg）
```

保存 11 个寄存器共 44 字节，再开 0x30 字节栈空间放三个 ParamStd。

`r7` 是钩点处已建立的栈帧指针，`[r7, #0x14]` 就是被钩的那两条指令原本要读的消息指针。

### 段二：判断是不是"开始曝光"

```asm
cmp.w  r8, #0
beq    cleanup                ; 消息为空，跳过
mov    r6, r8
ldrb   r3, [r6]               ; r3 = msg->type
cmp    r3, #4                 ; 0x04 = CAP_NOTIFY
bne    cleanup
ldrh   r6, [r6, #2]           ; r6 = msg->nid
movw   r3, #0x1001
cmp    r6, r3                 ; 0x1001 = START_EXPOSURE
bne    cleanup
```

就是这两个判断。不是拍摄通知、不是开始曝光，直接跳到清理段返回。

### 段三：算模块基址

```asm
adr    r4, #0                     ; r4 = 当前 PC
movw   r5, #0x4900
movt   r5, #0x19                  ; r5 = 0x194900
sub.w  r4, r4, r5                 ; r4 = PC - 0x194900 = libObj 基址
```

`adr r4, #0` 取 PC。Thumb 下 PC = 当前指令地址 + 4，且按 4 字节对齐：
`adr` 在 `0x1948FC`，所以 PC = `0x194900`。于是 `基址 = PC − 0x194900`，
后面所有 PLT 偏移都相对这个基准算。

这样就不用写死运行期地址，模块加载到哪都能算出基址。

### 段四：构造并投递播放请求

```asm
; ObjMsg(0x3410, 0x1120)
add    r0, sp, #0x18
movw   r1, #0x3410
movt   r1, #0
movw   r2, #0x1120
movt   r2, #0
movw   r6, #0xF7B8
movt   r6, #0x0F
add    r6, r4                     ; plt_ObjMsg_ctor
blx    r6

; ParamStd(soundId)  三个参数的 PID 由被调函数内部设置
add    r0, sp, #0x10
movs   r1, #7                     ; soundId = 0x07 CAUTION
movw   r6, #0x2B34
movt   r6, #0x10
add    r6, r4                     ; plt_ParamStd_ctor
blx    r6

add    r0, sp, #8
movs   r1, #1                     ; 0x1001 位置 = 1
... blx plt_ParamStd_ctor

add    r0, sp, #0
movs   r1, #0                     ; 0x1002 位置 = 0
... blx plt_ParamStd_ctor

; AddParam(msg, 0x1000, &p0)
add    r0, sp, #0x18
movw   r1, #0x1000
add    r2, sp, #0x10
... blx plt_AddParam

; AddParam(msg, 0x1001, &p1)
movw   r1, #0x1001
add    r2, sp, #8
... blx plt_AddParam

; AddParam(msg, 0x1002, &p2)
movw   r1, #0x1002
add    r2, sp, #0
... blx plt_AddParam

; Get(7) → 参数列表
movs   r0, #7
bl     #0x6117840
mov    r6, r0
cmp    r0, #0
beq    cleanup

; IssueCommandAsync(iface, &msg)
mov    r0, r6
add    r1, sp, #0x18
movw   ip, #0xd2a0
movt   ip, #0xf
add    ip, r4
blx    ip                        ; plt_IssueCommandAsync
```

**注意 `bl #0x6117840` 是相对调用，不是 PLT 桩。** 这是整个载荷里唯一一条 `bl`，
目标是 libObj 内部函数，距离在 ±16MB 内，安全。

### 段五：恢复现场，重放，跳回

```asm
cleanup:
add.w  sp, sp, #0x30
pop.w  {r0, r1, r2, r3, r4, r5, r6, r7, r8, ip, lr}
ldr    r4, [r7, #0x14]           ; 重放原第 1 条
ldrb   r3, [r4]                  ; 重放原第 2 条
b.w    #0x67FB22A                ; 跳回钩点 + 4
```

**重放的两条就是被覆盖的原指令。** 不重放的话，被钩函数会缺少 `r4` 和 `r3` 的正确值。

## 载荷铁律（每条都踩过坑）

| 规则 | 为什么 |
|---|---|
| 零 store 到绝对地址 | 写任何没证实可写的内存都会崩，有的地址看着能写其实是只读页 |
| 零跨段调用 | 跨段 `bl` 会覆盖 `lr`，返回时跳到垃圾地址。跨段一律用 `blx` + 算出的绝对地址 |
| callee-saved 全保存 | `r4-r8`、`sb`、`sl`、`fp` 必须保存。少存一个 `sb`(r9) 的版本按键瞬间重启 |
| 不调可能阻塞的函数 | 载荷跑在 CP 收包线程，阻塞就是整条流水线卡死 |
| 不碰 `r12`(ip) 除非已知 | 函数序言内部编译器会把 `r12` 当临时寄存器用，不能假定它可随意覆写 |
| 栈空间够用 | 开了 0x30 字节，三个 ParamStd + ObjMsg 都放得下。少开会踩到调用者的栈 |

已知偏差：`push` 44 B + `sub sp, #0x30` = 92 B。如果入口 SP 是 8 字节对齐，九个
`blx` 调用点的 `SP % 8 = 4`，不符合 AAPCS。Unicorn 自检只打印警告，不把它算作通过
条件；真机后果没有验证（截至当前没有观察到崩溃）。

## 为什么放 0x1948D8

- 在 libObj 的 r-x 段（`PT_LOAD` 权限决定可执行，不是 section 标志）
- 那里是个**从不被调用的函数**，覆盖掉没有副作用
- 这段死区共 328 字节（`0x1948D8`..`0x194A20`），载荷占 240，剩 88 字节，不碰相邻函数

试过但不行的地方：

| 位置 | 问题 |
|---|---|
| rw 段（如 0x15ABFA2C） | NX，不可执行，跳进去必崩 |
| ELF 文件里的零区 | 运行时被数据填满，覆盖了会改坏活数据 |
| `.rodata` 里的 20 KB 零区 | 文件里是零，运行时也不是零 |
| CautionConfig 段尾 | 和菜单数据结构冲突 |

**教训：文件里的零区不等于运行时空闲，必须先把运行时内存 dump 下来验证。**

## 重建载荷

```bash
python tools/build_payload/build_burst_only.py \
    --so backup/<时间戳>/usr_lib_libObj.so \
    --nid 0x1001 --sound 0x07
```

会生成完整 `.so` 和拆分的 `pay.bin` / `hok.bin`，并跑 18 项 Unicorn 仿真自检。

产物在 `tools/build_payload/out/`：

```
libObj.burst_nid1001s07.so        打好的完整 .so
libObj.burst_nid1001s07.asm.txt   反汇编清单
libObj.burst_nid1001s07.json      构建参数
libObj.burst_nid1001s07.bin/
    pay.bin        载荷正文 240 字节
    hok.bin        钩子 4 字节
    orig_hook.bin  钩点原厂 4 字节
    orig_pay.bin   载荷位置原厂 328 字节
```

**载荷的源码在 `build_burst_only.py` 的 `build_code()` 里**，是一个按参数生成汇编文本的
Python 函数。想改载荷逻辑就改那个函数。本文件前面几段贴的是它生成的汇编，方便对照。
自检覆盖：钩子跳转、载荷入口、重放、回跳、真实分发器、防误触发、零绝对写、无非法内存访问、
连拍 8 帧恰好 8 次发声。全过再上机。
