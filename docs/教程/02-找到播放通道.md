# 教程 02 · 找到播放通道

## 结论

Linux 侧调用 `MWF::ObjIf::IssueCommandAsync`，参数是一个 `ObjMsg` 加上若干 `ParamStd` 参数。
这是**异步**投递，不阻塞调用线程。

```
对象:    MWF::ObjIf（全局单例，GOT 里有指针）
方法:    IssueCommandAsync
消息:    ObjMsg(cate=0x3410, msgId=0x1120)
参数:    3 个 ParamStd<unsigned int, MWF::Param::Type8>
```

三个参数的 PID 和值：

| PID | 含义 | 值 |
|---|---|---|
| 0x1000 | soundId | 要播放的音效编号（本项目用 0x07 CAUTION） |
| 0x1001 | 播放类型 | 1（单次） |
| 0x1002 | 保留 | 0 |

最后调用 `Get(7)` 取参数列表，传给 `IssueCommandAsync`。

## 为什么必须异步

同步版本 `beepPlay` 会死锁。

原因：载荷在 CP 收包线程里调用。同步播放会等 RTOS 回执，而回执要经过同一条 CP 通道，
于是收包线程等自己，整条流水线卡死。表现是相机卡住，只能拔电池。

异步投递只是把消息塞进队列就返回，不等待。

## 消息结构的实证

`ObjMsg` 的构造和投递在反汇编里能完整看到。载荷里调用的两个 PLT 桩：

| 符号 | fileVA | 作用 |
|---|---|---|
| `plt_ObjMsg_ctor` | 0x0FF7B8 | 构造 ObjMsg |
| `plt_ParamStd_ctor` | 0x102B34 | 构造单个 ParamStd |
| `plt_AddParam` | 0x1027E4 | 把参数加进 ParamList |
| `plt_IssueCommandAsync` | 0x0FD2A0 | 投递 |

这四个 PLT 桩的偏移都写进 `tools/sigscan.py` 的内置特征表，换固件时可以重新定位。

## 这条通道能播什么

30 个可替换槽位里，priority ≤ 5 的能播。priority 6 的（含真实机械快门声）在本项目的测试里
没有声音，原因没定位到。见死路清单 D-03。

## 一句话

**Linux 侧没有喇叭，但可以向有喇叭的那颗核"点歌"。点歌用的是异步 IPC，不是本地播放 API。**
