# 教程 01 · 备份与读取固件

## 目的

在改动任何东西之前，把相机里需要恢复的内容完整备份到本地。

**这一步是必须的。** ILCE-7RM3A 没有官方固件包（见[固件介绍](../01-固件介绍.md)），
刷坏没有任何外部恢复材料。你自己那台相机上的备份是唯一的退路。

同时，备份下来的 `libObj.so` 是后面所有分析和修改的基础。

整个过程只读，零风险。

## 两种备份方式

备份可以自己做，也可以用本项目的工具。两种都行。

### 方式一：自己的工具

如果你已经有 dump 相机文件的手段（PMCA 的 `pull`、rclone、别的脚本都行），只要确认
这三样都在就行：

```
/usr/lib/libObj.so                  19 MB，补丁改的就是它
/usr/share/avsystemsound/*.bin      30 个音效文件
/usr/share/avsystemsound/beeplist.txt
```

关键是**把这些文件和它们的哈希记下来**。只有文件没有哈希，你不知道备份有没有坏。

### 方式二：本项目的工具

```bash
python tools/camera/a7r3a_backup.py
```

推荐用这个，因为它做了三件手工容易漏的事：

1. **自动列全** —— 不会漏掉某个音效文件
2. **交叉校验** —— 拉下来之后让相机自己算一遍哈希，和本地比。只比本地哈希是不够的，
   那只能证明文件没被改坏，不能证明它和相机上的一致
3. **识别状态** —— 告诉你备份的 `libObj.so` 是原厂还是已打补丁

跑完之后自己再验一次：

```bash
python tools/camera/a7r3a_backup.py --verify backup/<时间戳>
```

输出应该是：

```
清单 32 个文件    本地完整性 32 通过    交叉校验 32/32
libObj.so 原厂    音效 31/31

备份完整。
```

如果「交叉校验」不到 32/32，说明有些文件没校验成功，重新备份一次。

## 备份的时机：只能在打补丁之前

备份的是相机**当前**的 `libObj.so`。如果打补丁之后才备份，备份下来的就是补丁本身，
回滚不到原厂。

工具会识别并告诉你备份的是哪一种：

```
libObj.so 状态：原厂
  这是未修改的原始文件，回滚就靠它          ← 可以继续

libObj.so 状态：已打补丁（soundId 0x07 CAUTION）
  这是打完补丁的状态，不能用来回滚到原厂     ← 退出码 1
```

看到「已打补丁」的意思是你**已经没有原厂备份的机会了**，除非：

1. 按[持久化到闪存](06-持久化到闪存.md)的反向操作把补丁撤掉，冷启动，再备份
2. 或者接受这份备份只能恢复到「打补丁后的状态」

新手常犯的错是：先跟着教程打完补丁，听效果满意，然后想起来要备份。
这时候备份的文件已经是补丁版，原厂代码已经没了。

**⇒ 所以这一步放在教程第一篇，不是随便排的。**

## 原理

相机的 Linux 侧是一个完整的 Linux 系统。进服务模式后 PMCA 会建一个 shell 通道，
可以执行 `busybox` 命令，也可以通过 `camera.readFile()` 把文件拉回本地。

要备份的东西：

| 内容 | 大小 | 为什么 |
|---|---|---|
| `/usr/lib/libObj.so` | 19 MB | 补丁改的就是它。没有它无法回滚 |
| `/usr/share/avsystemsound/*.bin` | 156 KB | 30 个音效文件，替换前必须留原件 |
| `/usr/share/avsystemsound/beeplist.txt` | 4.6 KB | 音效索引 |
| `/proc/155/maps` | 小 | 地址对照表 |
| Backup 属性 | 小 | 音量、开关等设置 |

## 步骤

### 1. 让相机进服务模式

```bash
python tools/camera/a7r3a_status.py
```

这个脚本会自动切换模式并打印状态。

相机必须出现在设备管理器里，设备号 `054C:0336`（服务模式）。普通模式是 `054C:0D99`。

### 2. 完整备份

```bash
python tools/camera/a7r3a_backup.py
```

默认存到 `backup/<时间戳>/`。也可以指定：

```bash
python tools/camera/a7r3a_backup.py --out my-backup
```

它会做这些事：

```
· 读 /proc/155/maps 存成 maps.txt
· 列出 /usr/share/avsystemsound/ 下的文件
· 逐个拉回本地（19 MB 那个最慢）
· 对每个文件算 SHA256 和 MD5
· 写 manifest.json 和 README.md（含恢复步骤）
```

USB 不稳时会自动重试。拉不下来的文件会报错，不会跳过。

### 3. 校验备份

```bash
python tools/camera/a7r3a_backup.py --verify backup/<时间戳>
```

逐个文件重算 SHA256 并与清单比对。

**这一步必须做。** 备份坏掉和没备份是一样的，但更危险——因为你以为有。

### 4. 记录环境信息

```bash
python tools/camera/a7r3a_status.py --maps
python tools/verify_environment.py --check-all
```

把输出存下来。后面每一步的验证都要和这些值对比。

原厂 `libObj.so` 的 SHA256 应该是：

```
f1351204d2dd1c4033d427e09e7848fbbff0dd577abb205e00ef97bb4e6b81ed
```

不是这个值说明相机已经被改过，或者不是同一个构建。**先搞清楚再往下做。**

## 验收标准

```
· backup/<时间戳>/ 下有 32 个左右文件
· libObj.so 是 19,484,036 字节，SHA256 等于 f1351204…
· 30 个 .bin 文件都在
· --verify 全部通过
· maps.txt 里有 libObj.so 的基址
```

## 备份放在哪

建议三份，两份不同介质：

```
一份留在电脑上
一份拷到 U 盘或移动硬盘
一份传到网盘
```

19 MB 而已，不占地方。

## 安全说明

这一步全是读操作：不写文件、不写内存、不改设置。

唯一的风险是服务模式本身。拔线后相机回到普通模式，不会留下任何改动。

## 常见问题

**拉 libObj.so 一直失败**

19 MB 对 USB 是长会话，容易抖。工具会自动重试 4 次。还不行就：

- 换根短点的 USB 线
- 关掉其他占用 USB 的程序
- 先 `--no-libobj` 把音效备份下来，再单独重试大文件

**报「一个文件都没有拉下来」**

相机没连上或不在服务模式。检查设备管理器里有没有 `054C:0336`。

**SHA256 对不上 `f1351204…`**

先确认型号和固件版本。ILCE-7RM3（不带 A）或者不是 1.00，哈希肯定不一样，
本项目的所有地址也不能用。
