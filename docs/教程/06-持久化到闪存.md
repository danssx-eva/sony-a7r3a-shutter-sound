# 教程 06 · 持久化到闪存

**前提：必须先完成[备份](01-备份与读取固件.md)。** 这一步会覆盖闪存里 `libObj.so` 的
两个 1 KB 块，没有原厂备份写坏就回不来。而且备份只能在**打补丁之前**做——
如果你还没备份过原厂，先看[备份的时机](01-备份与读取固件.md)。

## 改的是哪两个块

`/usr/lib/libObj.so`，19,484,036 字节。改动落在两个 1 KB 块里：

| 块 | 文件偏移 | 改了什么 | 块大小 |
|---|---|---|---|
| A | `0xA31000` | 钩点 4 字节（`0xA31226`） | 1024 B |
| B | `0x194800` | 载荷 240 字节（`0x1948D8` 起） | 1024 B |

补丁覆盖 244 字节（块 A 4 + 块 B 240）。实际写入闪存是两块各 1024 字节，共 2048 字节；
其中与原厂不同的只有 238 字节 —— 载荷里有 6 个字节碰巧和原厂相同。

本项目**不提供**这两个 1 KB 块。块里除了本项目的补丁，其余是 Sony 的原始代码，
分发它们等于分发 Sony 二进制。

用工具生成：

```bash
python tools/persist/make_blocks.py \
    --so backup/<时间戳>/usr_lib_libObj.so \
    --hook 63f7579b
```

它会：

```
· 校验 .so 的整文件 SHA256 是不是原厂值
· 校验两个块的原厂 MD5（防止拿错构建）
· 写入钩子和载荷
· 校验改后的整文件 SHA256 是否等于记录值
· 输出 blkA.bin、blkB.bin 和 blocks.json（含块内偏移、块号、哈希）
```

输出到 `work/blocks/`。这一步不需要相机。

然后传到相机：

```bash
python tools/camera/push_files.py --file tools/inject/pw --dir work/blocks
```

传完会读回校验。

原厂：


打完载荷后（取决于载荷里的 soundId）：

```
soundId 0x04  d45ca8d7821b7a771555faab179ec268316d75acb4cb1a0ee8bae70453730e6a
soundId 0x07  d80aa1e00b84f5f719eb5e427bf760a06b81b6401a7550edada355d8f2d4a960
```

## 为什么不能用 busybox dd

**busybox 的 `dd` 写文件时会截断。**

实测：一个 100 字节的文件，`dd ... seek=50 count=2` 之后变成 52 字节。它用 `O_TRUNC`
打开目标文件。

相机只有 busybox，没有 `dd conv=notrunc`。所以要自己写一个。

## pw

`tools/inject/pw`（2,656 字节，静态链接的 ARM 程序）。
源码是 `tools/inject/pw_nolibc.c` + `tools/inject/pw_start.S`，
编译脚本 `tools/inject/build_pw.sh`。

```bash
/log/w/pw /usr/lib/libObj.so 0x194800 /log/w/blkB.bin
```

它的做法：

1. `open(path, O_WRONLY)` —— **不带 `O_TRUNC`**
2. `lseek(fd, offset, SEEK_SET)`
3. `write(fd, data, 1024)`
4. `fsync(fd)`
5. `close(fd)`

不依赖 libc，直接系统调用，所以拷到相机上就能跑。

编译方法：`sh tools/inject/build_pw.sh`（需要 ARM 交叉编译器）。
仓库里已经附了编好的 `pw`，不想编译可以直接用。

## 写入流程

```sh
# 1. 挂成可写
busybox mount -o remount,rw /usr

# 2. 写块（用 pw，不用 dd）
/log/w/pw /usr/lib/libObj.so 0x194800 /log/w/blkB.bin
/log/w/pw /usr/lib/libObj.so 0xA31000 /log/w/blkA.bin

# 3. 落盘 —— 这一步是关键
busybox sync
busybox fsync /dev/nflasha15
busybox sync

# 4. 挂回只读
busybox mount -o remount,ro /usr

# 5. 验证
busybox sha256sum /usr/lib/libObj.so
```

## `fsync /dev/nflasha15` 是必须的

`sync()` 只把文件系统的脏页交给块层，**不会**让 eMMC 把自己的写缓存刷下去。

少了 `fsync` 到块设备这一步，会遇到经典的假象：

```
刚写完 → 读回一模一样 → 重启 → 全部回滚
```

这个坑踩过一次，浪费了半天。

## 验证顺序

1. **写入后立即读回**：两个块逐字节比较，必须和源文件一致
2. **整文件 SHA256**：等于上面对应 soundId 的值
3. **冷启动**：拔电池，等十几秒，装回开机。`/proc/uptime` 归零才算真重启
4. **重启后再读一次 SHA**：仍然一致，说明落盘了
5. **读运行期钩点**：`0x067FB226` 是 `63 f7 57 9b`，说明从闪存自动加载了
6. **拍照验证**：单拍 1 声，连拍 5 张 5 声

## 块级写入的坑

**1 KB 块的写入是概率性的。** 同样的命令，有时写进去，有时不写。必须每块单独验证。

验证方法：

```sh
# 写完后单独读回这一块，和源文件比
# 块号 = 文件偏移 / 1024：A 是 10436，B 是 1618
busybox dd if=/usr/lib/libObj.so bs=1024 skip=10436 count=1 2>/dev/null | busybox md5sum
busybox md5sum /log/w/blkA.bin
```

两个 MD5 一致才算这一块成功，否则重写。不要指望"写两次就都成功"。

## 回滚

**顺序很重要：先撤钩子（块 A），再还原载荷（块 B）。**

反过来的话，两次写之间钩子还指着 `0x1948D8`，可那里已经变回原厂代码了——
这时按快门会跳进原厂函数的中间，崩。打钩子时要先写载荷再写钩子，回滚时正好相反。

先在电脑上从备份切出两个原厂块（不用相机）：

```bash
dd if=backup/<时间戳>/usr_lib_libObj.so of=blkA_orig.bin bs=1024 skip=10436 count=1
dd if=backup/<时间戳>/usr_lib_libObj.so of=blkB_orig.bin bs=1024 skip=1618 count=1
```

或者直接用仓库里的回滚工具，它会按正确顺序写两块并校验整文件 SHA：

```bash
python tools/camera/a7r3a_restore_all.py --so backup/<时间戳>/usr_lib_libObj.so
```

把两个块传到相机：

```bash
python tools/camera/push_files.py --file blkA_orig.bin --file blkB_orig.bin
```

手工回滚：

```sh
busybox mount -o remount,rw /usr
/log/w/pw /usr/lib/libObj.so 0xA31000 /log/w/blkA_orig.bin   # 先撤钩子
/log/w/pw /usr/lib/libObj.so 0x194800 /log/w/blkB_orig.bin   # 再还原载荷
busybox sync
busybox fsync /dev/nflasha15
busybox sync
busybox mount -o remount,ro /usr
```

原厂块从你自己的备份里取，见[备份与读取固件](01-备份与读取固件.md)。

回滚后整文件 SHA 应回到 `f1351204…`。

不要往 `/usr` 里另存整个 `.so` 的副本（19 MB 放不下）。先看 `busybox df -h /usr`，
剩余空间每台机器可能不同；临时文件用完就删。
