# 教程 05 · 打钩子

## 补丁

```
位置   libObj.so fileVA 0xA31226（运行期 0x067FB226）
原字节 7c 69 23 78      ldr r4,[r7,#0x14] ; ldrb r3,[r4]
补丁   63 f7 57 9b      b.w 0x05F5E8D8
```

钩子字节以十六进制形式给出，见[补丁产物](../patches/README.md)。原厂那 4 字节自己读：

```sh
busybox dd if=/proc/155/mem bs=1 skip=<钩点运行期地址> count=4 2>/dev/null | busybox xxd -p
```

## b.w 怎么算出来

`b.w` 是 Thumb-2 的 32 位无条件跳转，编码 T4：

```
11110 S imm10 | 10 J1 1 J2 imm11
```

目标 = 当前指令地址 + 4 + 符号扩展后的 imm32。范围 ±16 MB。

本项目距离：

```
目标 0x05F5E8D8 - 源 0x067FB226 = -0x089C94E  ≈ -8.6 MB
```

在范围内，直接一条 `b.w` 就能到，不需要中间跳板。

汇编方法：

```python
import keystone as K
ks = K.Ks(K.KS_ARCH_ARM, K.KS_MODE_THUMB)
code, _ = ks.asm("b.w 0x05F5E8D8", 0x067FB226)
# keystone 返回 list[int]，不是 bytes
assert bytes(code) == b'\x63\xf7\x57\x9b'
```

## 为什么 4 字节正好

原位置是两条完整的 16 位 Thumb 指令。4 字节补丁不会切开任何一条指令。

**这一条差点毁掉整个项目。** 早先视图钩错了一个地址（一个函数的最后 1 字节 + 下一个函数的前 3 字节），
4 字节补丁横跨了指令边界，返回地址落在指令中间，每次都崩。见死路清单 A 组。

判断方法：**钩点必须半字对齐（地址是偶数）**，然后用 capstone 反汇编确认这 4 字节
恰好是两条完整的 16 位指令。不要用「差值是不是 4 的倍数」判断——本项目的钩点
`0xA31226` 就不是 4 的倍数，但它是合法的。

## Thumb 位

ARM 的 `bx` / `blx` 用目标地址的 bit 0 表示目标状态：

```
bit0 = 1 → Thumb
bit0 = 0 → ARM
```

所以用 `bx` 跳 Thumb 代码时目标地址必须 `| 1`。

**但本项目的 `blx` 目标不是 Thumb 代码。** 它跳的是 PLT 桩
（`base+0x0FF7B8` 等），这些桩是 **ARM 代码**，目标地址必须**保持偶数**。
给 ARM 桩加 `|1` 会让 CPU 切到 Thumb 去执行 ARM 指令，必崩。

规则：跳 Thumb 代码 `|1`，跳 ARM 代码保持偶数。本项目 PLT 属于后者。

**踩过的坑**：跨模块跳板测试时 `bx` 到偶数地址，CPU 切到 ARM 模式执行 Thumb 代码，立刻崩。
表现是进菜单就重启，查了很久才发现是 Thumb 位。

## 打钩子的方法

内存注入（重启即失效）：

```bash
python tools/inject/inject_generic.py \
    --so tools/build_payload/out/libObj.burst_nid1001s07.so \
    --hook-va 0xA31226 --pay-va 0x1948D8 --pay-len 240
```

`--so` 要的是上一步生成的**完整 .so**（19,484,036 字节）。传 `out/` 里那个同名的
`.bin` **目录**（里面是 pay.bin / hok.bin）会被拒绝——工具会检查文件大小和钩点字节。

这个脚本会：
1. 从本地 `.so` 里取出载荷和钩子字节
2. 连相机、切服务模式
3. 写载荷到运行期地址
4. 写钩子到运行期地址
5. 读回验证

**顺序很重要：先写载荷，再写钩子。** 反过来会出现"钩子已生效但载荷还是旧内容"的窗口，
那一瞬间拍照会跳到垃圾地址。

## 内存版和闪存版的区别

| | 内存注入 | 闪存补丁 |
|---|---|---|
| 生效 | 立即 | 冷启动后 |
| 持久 | 重启即消失 | 拔电池仍在 |
| 风险 | 低，重试即可 | 写坏可能起不来 |
| 用途 | 调试、试参数 | 日常使用 |

调试阶段全用内存注入。确认稳定了再打闪存补丁，见 `06-持久化到闪存.md`。
