# 附录 · 结构规格

纯规格参考。原理和操作步骤在教程里。

## 一、音效文件格式

文件在 `/usr/share/avsystemsound/*.bin`。

### 块结构

每 32 字节一块：

| 偏移 | 内容 |
|---|---|
| byte 0 | 控制字节。bit0-3 是指数 `exp`，`scale = 1 << exp`；bit4 是预测器开关（原厂全是 1）；bit5-7 未用 |
| byte 1..31 | 31 个有符号残差，int8，-128..127 |

```
块数     = 文件大小 / 32
总采样数 = 块数 × 31
采样率   = 24000 Hz
声道     = 单声道
样本格式 = int16（解码后）
```

例：8640 字节 → 270 块 → 8370 采样 → 348.8 ms。

### 解码

```python
RATE = 24000
PRED = 60 / 64          # 0.9375，一阶预测器系数

def decode(raw: bytes) -> list[int]:
    out, last = [], 0.0
    for off in range(0, len(raw), 32):
        control = raw[off]
        scale = 1 << (control & 0x0F)
        for b in raw[off + 1:off + 32]:
            r = b if b < 128 else b - 256
            last = r * scale + (PRED * last if control & 0x10 else 0)
            out.append(max(-32768, min(32767, round(last))))
    return out
```

### 编码

每块搜索一个让残差不越界的指数，用上一块的末值做预测初值。

```python
def encode(samples: list[int]) -> bytes:
    out, last = bytearray(), 0.0
    for at in range(0, len(samples), 31):
        blk = list(samples[at:at+31]) + [0] * (31 - len(samples[at:at+31]))
        best = None
        for exp in range(10):
            step, pl, res, ok, maxerr = 1 << exp, last, [], True, 0
            for x in blk:
                r = round((x - PRED * pl) / step)
                if r < -128 or r > 127:
                    ok = False
                    break
                res.append(r)
                pl = r * step + PRED * pl
                maxerr = max(maxerr, abs(pl - x))
            if ok:
                best = (exp, res, pl, maxerr)
                if maxerr < step:
                    break
        exp, res, pl = best[:3] if best else (9, [0] * 31, last)
        out.append(0x10 | exp)
        out.extend(r & 0xFF for r in res)
        last = pl
    if len(out) % 64:
        out.extend(bytes(32))
    return bytes(out)
```

### 回环验证（软件自洽性检查）

把原厂文件解码，再用上面的编码器重编码，逐点比较：

```
Caution.bin（8640 B）：误差 1 / 20401 = 0.00%   [实测]
解码后样本范围 -17096 .. 20401
```

误差接近 0 说明解码模型正确。编造的系数会差几百上千。

## 二、播放消息

### 投递方式

```
对象:    MWF::ObjIf（全局单例，GOT 里有指针）
方法:    IssueCommandAsync
消息:    ObjMsg(cate=0x3410, msgId=0x1120)
```

三个参数，类型 `ParamStd<unsigned int, MWF::Param::Type8>`：

| PID | 含义 | 本项目取值 |
|---|---|---|
| 0x1000 | soundId | 0x07 |
| 0x1001 | 播放类型 | 1 |
| 0x1002 | 保留 | 0 |

流程：构造 ObjMsg → 构造 3 个 ParamStd → `AddParam` 三次 → `Get(7)` → `IssueCommandAsync`。

**必须异步。** 同步版本 `beepPlay` 在 CP 收包线程里会死锁。

### PLT 桩（fileVA）

| 符号 | fileVA |
|---|---|
| `plt_ObjMsg_ctor` | 0x0FF7B8 |
| `plt_ParamStd_ctor` | 0x102B34 |
| `plt_AddParam` | 0x1027E4 |
| `plt_IssueCommandAsync` | 0x0FD2A0 |

在 `tools/sigscan.py` 的内置特征表里，换固件可以重新定位。

## 三、CpMsg 结构

CP 收包循环收到的消息：

```
+0x00  u8   type      0x04 = CAP_NOTIFY
+0x01  u8
+0x02  u16  nid
+0x04  u32
+0x08  ...  payload
```

从 21 个构造函数和 4 个处理函数的反汇编交叉验证得出。

### nid 取值

| nid | 含义 | 频率 |
|---|---|---|
| 0x1000 | CAPTURE_START | 每次拍摄会话 1 次 |
| 0x1001 | START_EXPOSURE | 每帧 1 次 |
| 0x1002 | END_EXPOSURE | 每帧 1 次 |

实测：单拍 1 张 `0x1001` 出现 1 次；连拍 8 张出现 8 次，间隔约 101 ms。

## 四、菜单节点结构

40 字节：

| 偏移 | 字段 | 说明 |
|---|---|---|
| +0x00 | vtable | `0x163C4958`（`CmnViewSettingNode`） |
| +0x04 | subNodes | 子节点数组指针 |
| +0x08 | count | 子节点个数 |
| +0x0C | props | 属性组指针 |
| +0x10 | parent | 父节点 |
| +0x14 | depth | 层深 |
| +0x18 | selidx | 选中子项索引 |
| +0x1C | SRNum | 序号，渲染器用 `getSubItemBySRNum` 查行内容 |
| +0x20 | id | id |
| +0x24 | state | 0=不可选/隐藏，1=正常，2=选中，3-6=灰显 |

### 属性组与属性表

属性组 8 字节：`{ table_ptr, count }`

属性表每条 12 字节：`{ propId, type, value }`

| propId | 含义 |
|---|---|
| 0x00 | 标题资源 ID |
| 0x01 | 图标资源 ID |
| 0x06 | 帮助资源 ID |
| 0x0B | ? |
| 0x0C | 选项索引 |
| 0x0E | procId |
| 0x0F | 设置值 |
| 0x10 | 设置值 |
| 0x14 | 显示文本 ID |

### 渲染器的两个静默丢弃条件

```
① 行数 = getCountSelectable() = 子节点中 +0x24(state) != 0 的个数
② 第 i 行内容 = getSubItemBySRNum(i) → 比较 +0x1C(SRNum)，查不到则行空白
```

① 决定**行数**（不满足 → 这一行不存在）；② 决定**每行内容**（查不到 SRNum → 该行空白）。

### 音频信号属性表（实例）

运行期地址 `0x162D39F8`（CautionConfig 基址 `0x15AC0000` + fileVA `0x8139F8`）：

| # | propId | type | value |
|---|---|---|---|
| 0 | 0x00 | 0 | 0x0204E080 |
| 1 | 0x06 | 0 | 0x0204E44F |
| 2 | 0x0B | 1 | 2 |
| 3 | 0x0C | 1 | 4 |
| 4 | 0x0E | 1 | **0xA8**（procId） |
| 5 | 0x14 | 1 | 0 |

## 五、Backup 属性

### 音量

每个 soundId 一个字节，范围 0..7。

```
主通道 BKID = 0x2B008B - delta1[soundId]
副通道 BKID = 0x2B008B - delta2[soundId]
```

`delta1` / `delta2` 是固件里的静态表，不是公式。实测值：

| soundId | 主通道 BKID | delta1 | 副通道 BKID | delta2 |
|---|---|---|---|---|
| 0x04 FORCUSLOCK | 0x002B0022 | 0x69 | 0x002B0061 | 0x2A |
| 0x07 CAUTION | 0x002B0020 | 0x6B | 0x002B0059 | 0x32 |

默认值是 2，最大 7。

### 音频信号开关

```
BKID  0x01070026
值    01 00 00 00 = 开
      02 00 00 00 = 关
```

这一个属性同时门控所有提示音。关掉它，载荷发的播放请求会被丢掉。

### 其他常用属性

| BKID | 含义 | 实测值 |
|---|---|---|
| 0x01070175 | 风格当前 | 0..14 |
| 0x01070178 | 对比度当前 | 0..6 |
| 0x01070187 | 饱和度当前 | 0..6 |
| 0x0107018A | 锐度当前 | 0..6 |
| 0x01070B2C | 静音快门 | 02 = 启用 |
| 0x010713F2 | 快门类型 | 01 |

BKID 表是静态的，**不能动态注册新的**。

## 六、空间布局

**本节所有地址只对 ILCE-7RM3A 固件 1.00 的这一份构建有效。** 换固件版本必须重新定位，
见[特征码定位](特征码定位.md)。判据是 `libObj.so` 的 SHA256 等于 `f1351204…`。

### 模块基址（运行期）

```
libObj.so              0x05DCA000
libosal_uipc.so        0x04050000
viewUnified2.so        0x15008000
CautionConfig.so       0x15AC0000
ModelCautionConfig.so  0x0C4EA000
```

### 本项目占用的地址

| 用途 | 模块 | fileVA | 运行期 |
|---|---|---|---|
| 钩点 | libObj | 0xA31226 | 0x067FB226 |
| 载荷（240 B） | libObj | 0x1948D8 | 0x05F5E8D8 |
| RAM 标志 | libosal_uipc | — | 0x0405EFE0 |
| 音频信号属性表 | CautionConfig | 0x8139F8 | 0x162D39F8 |

### 哪些内存能放代码

| 位置 | 可执行 | 能放载荷 |
|---|---|---|
| r-x 段（`PT_LOAD` 权限 x） | 是 | 是 |
| rw 段 | 否（NX） | 否 |
| ELF 文件里的零区 | 运行时不一定是零 | 必须先 dump 验证 |
| `.rodata` 里的零区 | 是 | 一般被运行时数据占用 |

**判据是 `PT_LOAD` 段的权限，不是 ELF section 的标志。**

## 七、持久化

### 改动位置

| 块 | 文件偏移 | 改动 |
|---|---|---|
| A | 0xA31000 | 钩点 4 字节（0xA31226） |
| B | 0x194800 | 载荷 240 字节（0x1948D8 起） |

补丁覆盖 244 字节；实际写入两块共 2048 字节，与原厂不同的 238 字节。
