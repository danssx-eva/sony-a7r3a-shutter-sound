# 踩过的坑

操作层面踩过的坑，按代价排序。逆向方法上的死路见
`docs/附录/死路清单.md`。

## 一、换音效忘了恢复别的槽位

**症状**：对焦提示音变成了快门那声咔嚓，而且和快门一样响。

**原因**：分了两个阶段做。

1. 最早让 soundId `0x04`（FORCUSLOCK，对焦锁定音）响，把
   `Dslr_Emnt_High_FocusLock.bin` 换成了响亮的咔嚓声，并把它的主副通道音量
   （`0x002B0022`、`0x002B0061`）从 2 拉到 7。
2. 后来改用 soundId `0x07`（CAUTION），替换 `Dslr_Emnt_High_Caution.bin`，
   音量 `0x002B0020` 设 7。
3. **没把第 1 步的改动撤掉。**

于是相机上同时存在两处改动：对焦槽位是咔嚓声 + 音量 7，快门槽位也是咔嚓声 + 音量 7。
对焦和快门听起来一样。

同时还发现另外三个文件是更早期「批量替换测试」的遗留：
`T_Menu_Open`、`T_Select`、`WPS_PBC`。

**修复**：把 4 个文件恢复原厂（从固件包取），音量 `0x002B0022` 和 `0x002B0061`
还原成 2。`Caution` 保持本项目的版本和音量 7。

**规则**：

- 换哪个槽位就只调那个槽位的音量，不碰其他 soundId
- 每做一次替换，记下来：哪个 slot、哪个 BKID、原值多少
- 实验性质的替换要当天恢复，不要留到第二天

## 二、USB 连接不稳定

**症状**：

```
usb.core.USBError: [Errno None] b'libusb0-dll:err [_usb_reap_async] reaping request failed'
pmca.usb.driver.generic.GenericUsbException
RuntimeError: 未找到服务模式设备 0x0336
```

**原因**：不是代码问题。表现是随机的，同一个脚本连续跑，有时成功有时失败。
推断和以下因素有关：

- Windows 的 libusb0 驱动在长会话后状态不稳
- 残留的 python 进程占着 USB 句柄
- 相机侧服务模式会话超时

**应对**：

1. **每次操作前先清干净残留进程**

   ```powershell
   Get-Process -Name python -ErrorAction SilentlyContinue |
       ForEach-Object { Stop-Process -Id $_.Id -Force }
   ```

2. **操作之间等 4-6 秒**，不要连续立刻重连

3. **大文件分成小段传**，每段不超过 2048 字节，失败重试

4. **关键操作要读回验证**，不能只看命令返回码

5. 反复失败时先把相机拔下来再插上，切一次普通模式再切服务模式

**这条不是可选项。** 本项目所有成功的操作背后都有若干次失败重试，脚本里必须带重试
和读回校验，否则会误判"没写进去"或"写进去了"。

## 三、busybox dd 会截断文件

**症状**：写闪存后文件变短。

**原因**：busybox 的 `dd` 用 `O_TRUNC` 打开目标文件。没有 `conv=notrunc` 选项。

**实测**：一个 100 字节的文件，`dd ... seek=50 count=2` 之后变成 52 字节。

**修复**：自己写 `tools/inject/pw`，`open(path, O_WRONLY)` 不带 `O_TRUNC`。见
`../教程/06-持久化到闪存.md`。

## 四、只比文件头部就以为写对了

**症状**：音效没变，但校验"通过"。

**原因**：只比前 32 字节。如果新音效前面是静音、后面才是声音，头部会一致。

**修复**：比**整个文件**的 MD5，不是前几个字节。

## 五、sync 之后以为落盘了

**症状**：当场读回一模一样，重启全部回滚。

**原因**：`sync()` 只把文件系统的脏页交给块层，不让 eMMC 刷自己的写缓存。

**修复**：`fsync` 到块设备 `/dev/nflasha15`。见 `../教程/06-持久化到闪存.md`。

## 六、普通 reboot 以为重载了

**症状**：改了音效，`reboot` 之后没变化。

**原因**：音频资源在启动早期加载，且这台机器的启动走 WBI 热启动快照，普通
`reboot` 不一定重载 RTOS 侧。

**修复**：拔电池，等十几秒，装回开机。`/proc/uptime` 归零才算真重启。

## 七、改完属性没重启就判断失败

**症状**：改了音量属性，回读是 7，但听起来没变。

**原因**：音量在上电时从 Backup 读进内存。改属性只改存储，不改当前运行状态。

**修复**：改完拔电池重启。

## 八、1 KB 块写入是概率性的

**症状**：同样的写入命令，有时生效有时不生效。逐块看，有的块写了有的没写。

**修复**：每个 1 KB 块单独写、单独读回、单独比对 MD5。不要指望一次全成功，
也不要因为整文件 SHA 变了就认为所有块都对了。

## 九、连相机前没确认在哪个模式

相机的 USB 模式有两种：

```
普通模式  054C:0D99
服务模式  054C:0336
```

脚本默认按服务模式连。如果相机在普通模式，会报"未找到服务模式设备"。
PMCA 能自动切换，但切换需要时间，切换期间的重连会失败——这也是坑二的一部分。
